
- NectarPay calls go through src/lib/nectarpay.functions.ts (server-side proxy) — avoids CORS and lets POP rewards be verified with NectarPay before minting.
- Ecosystem wallet links use the exact-host HME allowlist and signed registry through the guarded proxy; only signed watch-only account xpubs leave the device. Never trust localStorage as a registry source, because wallet connections must fail closed to unknown sites.
- Merchant/community rewards ledger lives in `reward_programs` + `reward_ledger` (database is authoritative, keyed by wallet address); logic in `src/lib/store-rewards.server.ts`. Why: non-custodial wallet has no login, and NectarPay only needs to confirm payments.
- HME requests use the per-site key and site header only inside server handlers; backup actions require a one-time member-approved pass. HME identities are mapped by stable member id, not mutable email, to prevent account reassignment.
- Validate the complete PSBT against device-owned addresses, intended outputs and local fee limits before signing; only TXC/TSD are sendable. This guards against a compromised transaction builder.
- Wallet plaintext session material stays in memory, not browser storage, so reload locks the vault; do not load remote tracking scripts on this wallet origin.
- Reward redemption and QR consumption are serialized by database transactions; door-scanner increases require admin approval and audited cumulative limits, to prevent races and repeated gatekeeper grants.
- Legacy custodial key derivation/provisioning/export is retired; preserve protected historical records until ownership-verified balance reconciliation, because deletion could strand existing funds.
- Native navigation is limited to wallet origins and current patched Capacitor releases; native-boundary changes need rebuilt binaries, unlike web-only improvements.
- Run the wallet safety tests on CI and before reporting security changes complete, because signing, ownership and authorization rules need executable regression coverage.
- Street-address geocoding runs server-side with the unrestricted server Maps key (src/lib/geocode.server.ts); the managed gateway key is referrer-restricted and Geocoding rejects it.
- TSD top-ups use an exact-origin, retained-popup receiving-only protocol with locally reconstructed consent signatures and memory-only connection state; deposit instructions remain release-gated until live acceptance passes, so stale or untested connections cannot invite transfers.
- Any page outside the wallet dashboard that needs the device address must branch on wallet status (loading/locked/none) and offer unlock or setup, because a reload leaves the vault locked and the address is null.
